# model3d 重构方案

## 目标与边界

本次重构调整职责归属、组件复用、可维护性与建模交互。用户明确宣布“正式完工”之前允许直接调整项目数据格式，不保留旧数据迁移或兼容逻辑。几何引擎继续使用 Three.js，Vue 组件不直接承担几何算法。

## 分层方案

1. **数据与引擎层**：`types/` 定义文档契约，`stores/` 负责持久化，`engine/` 负责几何、草图边框、相机与导出。
2. **状态层**：`composables/` 管理跨组件状态。当前已拆出全局单位和撤销历史，后续按业务边界迁移，不为每个小函数额外建文件。
3. **组件层**：
   - `layout` 处理固定项目 Sidebar，项目名、历史、帮助、导出与实体树统一集成；
   - `modeling` 处理建模工具容器；
   - `sketch` 处理草图具体工具；
   - `entity` 处理实体树；
   - `ui` 提供无业务状态的通用按钮、菜单、图标和 `MinimalRange` 极简滑杆。
4. **配置层**：`const.ts` 保存规范常量，`configs.ts` 保存可配置选项，`colors.ts` 统一颜色。配置必须有用途注释并由实际代码引用。
5. **文档层**：`AGENTS.md` 是目录依据，`DEV.md` 是交互约定，本文件记录结构与变更历史。

## App 编排原则

App 可以保留跨组件的建模操作状态，但固定 Sidebar、建模工具条、草图工具条和约束区不再重复维护模板。通用 UI 不直接访问 document 或 Viewport，统一通过 props/emits 通信。

### App 业务模块

- `useProjectLibrary` 负责项目记录、自动保存和导入导出；`utils/projectYaml.ts` 统一紧凑 YAML 编解码，IndexedDB 保存完整 ProjectRecord 对应的 YAML 文本，规则见 `docs/PROJECT_YAML.md`；`useDocumentEntities` 负责实体、文件夹、平面和实体树操作。
- `useModelingOperations` 持有拉伸/布尔操作草稿，处理直接编辑与历史回改。
- `composables/sketch/useSketchState` 持有草图草稿、选择与派生状态；`useSketchSession` 负责草图生命周期、持久化和尺寸操作；`useSketchEditing` 负责点边选择、拖拽、裁剪和控制柄。
- `useSketchConstraints` 负责约束交互、历史与回滚；`engine/sketchConstraintChain` 只负责无 Vue 依赖的关联约束求解。
- `useSketchAssets` 负责图片/SVG 导入、资产选择、比例锁、尺寸和整体缩放；`useEdgeTreatmentOperations` 负责圆角/倒角事务、重复编辑与取消。
- `useSketchAdvanced` 负责三步对称临时状态和草图二维变换；`engine/sketchAdvanced` 负责扇区裁剪、径向变换和复合轮廓几何，`SketchAdvancedOverlay.vue` 只负责画布与操作条。
- App 保留共享文档状态、跨模块命令和 Viewport 回调编排。跨域能力通过窄接口或延迟回调注入，避免项目、建模与草图模块循环引用。

## Viewport 分层

- `components/viewport/Viewport.vue` 只负责创建/销毁 `Viewport`、传递原有 callbacks，并渲染投影后的 Vue 覆盖层。
- `engine/Viewport.ts` 是兼容既有调用方的轻量门面，负责模块组装、公共方法转发和草图模式切换协调。
- `ViewportEngine` 持有 Scene、WebGLRenderer、灯光、网格/阴影、resize 和渲染循环；`CameraController` 持有相机、OrbitControls、视角切换、fit、动画和比例尺。
- `InfiniteGrid` 使用局部平面 shader 坐标绘制自适应格距和 5 倍主线，格距在每个数量级只取 1 和 5，原点 X/Z 轴分别读取 `AXIS_COLORS.x` / `AXIS_COLORS.z`；`gridScale` 计算格距与约 150px 整数段比例尺，网格以 orbit target 的世界半径在 200%–300% 区间淡出。
- `SceneSynchronizer` 负责 ModelDocument 到 Three.js 的同步，以及选择、隔离、剖切和显示模式；`SectionRenderer` 使用逐实体 stencil 正反面计数与平面封口生成斜纹实心断面，正反面材质共享实时剖面，源几何不进入选择和导出；`HatchMaterial` 统一向草图填充和剖视端盖注入平面 UV 斜纹。`SketchRenderer`、`MeasurementRenderer`、`GuideRenderer` 分别负责草图、测量和拉伸/直接编辑辅助内容。
- `InteractionController` 统一接收 pointer/key 事件，持有草图拖拽、框选、直接编辑等手势状态；`GizmoDragController` 独立处理三维/草图坐标球点击、拖动与取消清理；`GeometrySelector` 负责连通曲面缓存、面高亮数据、实际轮廓边拾取结果和所选实体/面的统计。
- `buildBooleanRegions` 按 Venn 成员关系生成互不重叠的独立区域；`BooleanPreviewController` 只管理这些区域的透明材质/边框、mini +/- 和 hover 呼吸，不叠加源模型。结果实体仍由 `useModelingOperations` 在完成时写入 document。
- `ToolPanels`、`ModelingOperationBar` 和 `ViewportUtilities` 分别承载左侧命令弹层与右侧实体参数、顶部流程操作和底部视口工具；`OperationBar` 提供统一左对齐顶部结构与红色关闭按钮，`FloatingPanel` 提供可复用半透明浮层与可选箭头。`ViewportHints` 统一右侧提示避让布局，`ModelingHints` 按 3D 工具和选择生成内容。App 只组合组件并转发状态/事件。

- `OverlayController` 只保存普通业务数据、世界坐标和可选屏幕偏移；每帧投影后由 `ViewportOverlay.vue` 渲染草图尺寸、箭头旁 Extrude/Face Extrude 输入、单位、约束锁、标注和面向相机的 Boolean mini +/-。草图尺寸与边锁通过 `edgeKey` 配对，同边锁嵌入尺寸控件，独立边锁居中，避免重叠和缩放偏移。Mesh、Material、Scene 不进入 Vue 响应式状态，不再使用 CSS2DRenderer。
- `AppButton` 统一流程按钮的类型、尺寸、禁用态和圆角；`EntityTree` 自持内联重命名编辑态，通过事件写回 document。

销毁顺序为交互监听、TransformControls、相机辅助器、场景/各渲染器资源、渲染核心；Vue 组件卸载时统一触发，App 不再重复 dispose。

## 可访问性与样式

新增组件使用 scoped SCSS、原生 button、可见焦点样式和 aria-label。既有全局样式逐步收敛，不在一次重构中做无关视觉重排。

## 实体几何与交互模块

- `engine/topology/`：渲染顶点对应、实体邻接、surface domain、逻辑面/边及版本来源映射。
- `engine/modeling/`：Manifold WASM 生命周期、闭合扫掠体、Face Extrude、提交验证和直接编辑事务；`BakedGeometry.ts` 与 `FeatureReferences.ts` 负责提交烘焙及删除源对象后的 History 引用解除。
- `engine/viewport/DirectDragController.ts`：面/边箭头的绝对拖拽投影、RAF 合并、结束与取消。
- `SketchAssetRenderer` 负责图片/SVG 整体轮廓、viewBox 角点和尺寸覆盖层；`SketchAssetDragController`、`SketchGuideController` 分别持有资产手势与参考匹配，避免主 InteractionController 超过职责和行数边界。
- `engine/modeling/EdgeTreatments.ts` 从原始直线凸边生成圆角/倒角切削体；`VertexTreatments.ts` 以 `trimByPlane` 生成角倒角，`VertexRoundingGeometry.ts` 用连续四次三角 Bézier 曲面构造外凸角部切削体，与平面相切并在入射边 radius 处终止，不形成凹槽或圆柱，其他角点保持不变。渲染法线在三个棱边终止奇点按原平面拆分，merge vectors 继续维护拓扑对应。边和角共用有符号尺寸事务，内拖为正圆角、外拖为负倒角。`SceneSynchronizer` 保留最终显示网格与不写色、不导出的基础代理；代理除剩余面偏移外，仅为 Vertex Rounding 开放原顶点和未处理入射边的选择/编辑，边处理源边继续排除。生成面通过 `generatedTreatment` 和 treatment ID 继续编辑，`BakedGeometry` 保留未切削基体，防止重复切削。
- `engine/viewport/EdgePicker.ts`、`TopologyEdges.ts`：逻辑边显示、CSS 像素拾取、遮挡与 Select Through 输入。
- `GeometrySelector` 只负责将命中转换为 logical face/edge anchor；`SceneSynchronizer` 一次性发布 mesh、拓扑、显示边和来源关系。
- `GeometryAnchor` 在视口层保存 owner、矩阵快照和代理来源；`GuideRenderer.updateAnimation` 在矩阵变化时刷新 active 与粗箭头，`GeometrySelector.rebindAnchor` 在场景重建后按来源和带符号法向重取当前面，并对所有 `generatedTreatment` 生效，不再只处理 `type=face`。`applyMeshEdgeTreatments` 随 mesh 发布 resolved treatments，保证面编辑后的圆角曲面分类、选择和 active 使用相同坐标。`Viewport.sync` 统一执行重绑，Transform 和 Face Extrude 不再依赖 blur 或独立世界坐标补偿。
- 3D 草图通过单个命中即可解析独立 `profileFace`，选择状态明确为 `face`；只有 Ctrl/Command 累加，开放线无封闭面时不回退到整个草图或边选择。草图编辑 active 面由 `SketchRenderer.refreshFaces()` 按最新 document 重建。
- `engine/sketchConstraintSolver` 使用全局 Gauss-Newton 联合求解约束，替代逐边顺序覆盖；`sketchConstraintChain` 只保留调用入口和变更计数，UI 候选优先级、固定点及回滚契约不变。参考规则只表达双向关联，不再长期优先保护参考物。
- `sketchGuides` 统一操作点参考匹配，`InteractionController.sketchSelectionAnchor` 计算选中内容中心，`sketchDragEdgeStart` 提供线段另一端方向锚点；`computeSketchFaces` 与 `buildSketchRegionPreviews` 用回归保证约束后的面一致。
- `engine/importers.ts` 使用 Three.js 官方 STL/OBJ/GLTF loaders，导入结果转为带法线的 baked `meshGeometry`，不依赖服务端或外部纹理。`useProjectLibrary` 分离 3D 网格导入和 YAML 项目导入，工具栏不再提供搜索/工具入口。
- `tsconfig.model3d.json` 与 `scripts/git-hooks/pre-commit` 将 `noUncheckedIndexedAccess` 检查固定到提交流程，空候选等索引问题必须在 commit 前处理。
